# MenuManager 리팩토링 계획 및 주의점

## 목적
- menu-manager.js의 과도한 비대화/복잡화 해소
- 각 메뉴/버튼/모달별로 폴더 및 파일 분리 (Next.js 스타일)
- 유지보수성, 확장성, 가독성 향상

## 폴더 구조 예시
```
menu-module/
  menu-manager.js         // 메뉴 엔트리/라우팅/공통 로직만
  menu-config.json
  buttons/
    itemGuide/
      openGuide/
      enchantInfo/
      abilityInfo/
      userSearch/
    settings/
      programInfo/
      profileLink/
      showItemStats/
      wikiLink/
      lanisLink/
```

## 리팩토링 진행 순서
1. **분리 대상 선정**: 가장 독립적이고 의존성 적은 버튼/모달부터 분리 (ex. 프로그램 정보, 어빌리티 정보)
2. **공통 유틸/스타일 분리**: 중복되는 함수/스타일은 별도 파일로 이동
3. **menu-manager.js 최소화**: 메뉴 엔트리/라우팅/공통 이벤트만 남기고, 실제 동작은 각 모듈에서 담당
4. **점진적 분리**: 한 번에 전체 분리 X, 1~2개 기능씩 분리 후 정상 동작 확인하며 진행
5. **분리 후 원본(menu-manager.js)에서 해당 코드 반드시 삭제**
6. **분리한 함수/모듈은 반드시 menu-manager.js에서 import 및 함수 호출 방식으로 연결해야 함 (그렇지 않으면 메뉴 동작이 안 될 수 있음)**
7. **테스트 및 검증**: 각 분리 후 기존 기능(모달, 필터, 검색 등) 정상 동작 확인
8. **문서화**: 각 버튼/모달별 역할, import/export 방식, 의존성 명확히 주석/문서화

## 주의점 및 체크리스트
- [ ] **전역 상태/공유 변수**: menu-manager.js에서만 관리, 각 모듈은 props/인자만 사용
- [ ] **이벤트 중복/충돌**: 전역 이벤트 리스너 중복 방지, 각 모달/버튼은 mount/unmount 시 이벤트 관리
- [ ] **스타일 충돌**: 클래스명 네이밍 규칙 통일, 중복 방지
- [ ] **import/export 경로**: 상대경로/절대경로 혼동 주의, index.js에서만 외부 노출
- [ ] **기존 기능 100% 유지**: 리팩토링 전후 모든 메뉴/모달/검색/필터/토글 등 정상 동작 확인
- [ ] **점진적 커밋/롤백**: 각 단계별 git 커밋, 문제 발생 시 빠른 롤백 가능하도록 관리

## 예상 문제 및 대응
- **의존성 꼬임**: 함수/상태가 여러 모듈에 걸쳐 있을 경우, 공통 유틸/상태 관리자로 분리
- **이벤트 버블링/중복**: 각 모달/버튼 mount/unmount 시 이벤트 등록/해제 명확히
- **테스트 누락**: 분리 후 모든 버튼/모달/검색/필터/토글 등 직접 클릭/입력 테스트 필수
- **코드 중복**: 공통 로직은 utils.js 등으로 이동, 각 모듈에서 import

## 진행 방식
- 본 md파일을 항상 참조하며, 각 단계별 체크리스트를 지키며 진행
- 분리 후 반드시 기존 기능과 UI가 100% 동일하게 동작하는지 확인
- 문제가 발생하면 즉시 문서에 기록하고, 원복/수정 후 재진행
