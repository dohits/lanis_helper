# CURSOR AI 프로젝트 준수사항

이 문서는 Lanis Helper 프로젝트에서 **CURSOR AI(코드 어시스턴트, AI 모델 등)**가 코드를 생성, 수정, 리팩토링, 문서화할 때 반드시 준수해야 할 규칙과 주의사항을 안내합니다.

## ⚠️ AI 모델 필수 준수사항

- **보안**: XSS, CSRF, 개인정보 유출 등 보안 취약점이 발생하지 않도록 할 것
- **저작권**: 외부 코드/데이터/모델 사용 시 라이선스 및 저작권을 반드시 확인할 것
- **데이터 보호**: 개인정보, 민감정보, 게임 계정 정보 등은 절대 수집/저장/전송하지 말 것
- **API 사용**: 공식 API만 사용, 비공식/불법 API 사용 금지
- **오용 방지**: AI가 생성하는 코드가 게임 규칙, 커뮤니티 가이드라인, 법률을 위반하지 않도록 할 것
- **설명/문서화**: 새로운 기능/코드 추가 시 반드시 문서화 및 주석 작성
- **테스트**: 생성한 코드는 충분한 테스트 후 적용
- **파일 구조**: src/, docs/, dist/ 등 폴더 구조를 반드시 준수
- **.gitignore**: 빌드 산출물, 의존성, 임시파일 등은 커밋하지 않음
- **문서 최신화**: 코드/구조 변경 시 README.md, docs/ 등 문서도 반드시 최신화

## 📝 커밋 메시지 규칙

### 기본 형식
```
타입: 변경 요약 (v버전)

- 주요 변경사항 1
- 주요 변경사항 2
- ...
```

### 커밋 타입
- feat: 새로운 기능 추가
- fix: 버그 수정
- refactor: 코드 리팩토링
- docs: 문서 수정
- style: 코드 스타일 변경
- test: 테스트 추가/수정
- chore: 빌드/보조 도구 변경

### 예시
```
feat: 사용자 검색 기능 추가 (v1.4.0)

- 사용자 검색 모달 기능 구현
- XSS 방지를 위한 다층 보안 검증
- 현재 페이지에서 사용자 프로필로 이동
- 버전 1.4.0으로 업데이트
```

## 📝 코드 스타일 및 개발 가이드

- 한국어 주석 사용, 의미 있는 변수명, 일관된 들여쓰기
- 기능 추가 시: 1) 기능 구현 2) 보안 검증 3) 버전 업데이트 4) 커밋 메시지 작성 5) 푸시
- 입력값 검증 및 sanitization 구현, HTML 엔티티 인코딩 사용
- 새로운 기능/코드 추가 시 반드시 문서화 및 주석 작성
